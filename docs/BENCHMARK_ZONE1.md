# Звіт Зони 1 (Зріз 2): Порівняння Greedy LZ77 проти Lazy Greedy LZ77 (Issues #11–#13)

## 1. Параметри експерименту
- **Модуль:** `SmartSecureArchiver.Core.Compression` (`Lz77Parser`, `HuffmanCodec`, `BlockCompressor`)
- **Параметри формату SARC v1:** вікно `window_size = 32768` байт, `MIN_MATCH = 3`, `MAX_MATCH = 258`, канонічний Гаффман із 3 деревами (`LIT`, `LEN`, `DIST`, коди $\le 15$ біт, MSB-first).
- **Корпус:** `team/corpus/` (21 файл, 7 груп типів файлів `0..6`, сумарний розмір 329 903 байти).
- **Методика вимірювання часу:** `System.Diagnostics.Stopwatch` (мінімальний час із 3 прогонів після попереднього прогріву JIT, окремо час стиснення + розпакування).
- **Контроль коректності:** для кожного файлу в обох режимах перевірено побайтовий збіг після декомпресії (`original == restored`).

## 4. Висновки
1. **Якість стиснення:** `Lazy Greedy LZ77` стабільно дає менший або рівний розмір стиснених блоків на текстах (`група 0`), вихідному коді (`група 1`), структурованих даних (`група 2`), растрі (`група 3`) та виконуваних файлах (`група 4`), оскільки відкладений на 1 байт вибір дозволяє знайти суттєво довші збіги.
2. **Швидкодія:** `Greedy LZ77` працює швидше при стисненні, оскільки не виконує додатковий пошук збігу на позиції `pos + 1`. Час декомпресії в обох режимах практично однаковий (декодер `Lz77Parser.Decompress` не залежить від способу пошуку збігів).
3. **Нестисливі дані (`група 5` та високоентропійні файли `групи 6`):** для вже стиснених файлів (`.z`) та випадкового шуму обидва алгоритми коректно визначають `coded_len >= raw_len` і автоматично перемикають блок у режим `NO_COMPRESSION` (`block_flags = 0x01`) без роздування розміру блоку.
