# Bychkov.arc — Розумний захищений архіватор файлів SARC v1

Семестровий проєкт (Варіант 2) із дисципліни «Алгоритми та оптимізація програмних рішень».

## Про проєкт

* **Ідентифікатор формату:** `SARC` (версія `1`, суворо за `FORMAT_SPEC_P2.md`)
* **Рівень складності:** Базовий (для всіх зон відповідальності, стеля D1 = 0,8)
* **Цільова платформа:** .NET 8.0 (C#)

### Що робить система?
Консольний архіватор та розархіватор файлів бінарного формату **SARC v1**:
1. **Аналіз вхідних даних:** приймає один або декілька файлів будь-яких типів. Багатошаровий перцептрон (MLP) аналізує кожен файл за вектором із 6 груп статистичних ознак, класифікує його на один із семи типів (`0…6`) та визначає стратегію: стискати чи зберігати без стиснення (`NO_COMPRESSION`), якщо стиснення неефективне.
2. **Стиснення:** розбір на повтори через жадібний / лінивий LZ77 (вікно 32 КБ, збіги `3…258`) та побітове кодування канонічним Гаффманом (три окремі дерева `LIT`, `LEN`, `DIST` із максимальною довжиною коду 15 біт, MSB-first).
3. **Пакування в томи:** розбиття великих файлів на блоки та оптимальний розподіл по томах фіксованого розміру (`max_volume_bytes`) за допомогою точного алгоритму динамічного програмування для задачі про рюкзак 0/1 (із порівнянням із жадібним алгоритмом за $v/w$).
4. **Криптографічний захист:** схема Encrypt-then-MAC — одноразова генерація ключів на архів через `PBKDF2-HMAC-SHA256` (100 000 ітерацій, 64 байти $\to K_{\text{enc}}, K_{\text{mac}}$), шифрування `AES-256-CTR` (унікальний 12-байтний `nonce` на кожен том, лічильник блоків з `1`) та код автентичності `HMAC-SHA256`, який перевіряється у постійний час **до** розшифрування.
5. **Оптимізація параметрів:** генетичний алгоритм (3 гени: `window_size`, `min_match`, `no_comp_threshold`, турнірна селекція, кросовер, мутація, елітизм) максимізує підсумкову метрику якості $Q = \alpha S + \beta T$.
6. **Відновлення:** побайтово точне та атомарне відновлення вихідних файлів (`original == restored`) із перевіркою `CRC32` та `orig_size`.

## Основні ризики та план їх пом'якшення (Зріз 0)

| № | Ризик | Вплив | План пом'якшення |
|---|---|---|---|
| 1 | Побайтова або побітова несумісність із `FORMAT_SPEC_P2.md` (Big-Endian, порядок бітів MSB-first, 15-байтний запис блоку). | Неможливість прочитати еталонні архіви `ref_*.arc` ($Q = 0$). | Використання `BinaryPrimitives` (ADR-02) та рання перевірка парсера і декодера на контрольному прикладі `ref_01_single_file.arc` (розділ 8 специфікації). |
| 2 | Перевищення максимальної довжини коду Гаффмана (понад 15 біт) або неповне дерево при читанні пошкоджених даних. | Відмова кодування або падіння на `bad_*.arc`. | Двофазна побудова length-limited Huffman та цілочисельна перевірка рівності Крафта $\sum 2^{15-L_i} == 32768$ (ADR-03). |
| 3 | Повільна робота при багатотомності через повторний виклик `PBKDF2` (100 000 ітерацій) або велику таблицю ДП-рюкзака. | Просідання компоненти швидкодії $T$ у метриці $Q$. | Виведення ключів `PBKDF2` рівно один раз на архів (ADR-04) та попередня фіксація таблиці файлів тому (ADR-05). |
| 4 | Блокування інтеграції через затримку окремої алгоритмічної зони. | Затримка збирання наскрізного конвеєра. | Чіткі C#-інтерфейси у `SmartSecureArchiver.Core` (ADR-01) та робота через базовий режим `NO_COMPRESSION` до підключення всіх оптимізацій. |

## Збірка, тестування та запуск

Збірка рішення:
```shell
dotnet build SmartSecureArchiver.sln
```

Запуск усіх автоматичних тестів однією командою:
```shell
dotnet test SmartSecureArchiver.sln
```

Використання консольної утиліти (`SmartSecureArchiver.Cli`):
```shell
# 1. Архівування файлів
dotnet run --project src/SmartSecureArchiver.Cli -- archive -i file1.txt file2.bin -o archive.arc -p "algo2026"

# 2. Розархівування (підтримує один або декілька томів у будь-якому порядку)
dotnet run --project src/SmartSecureArchiver.Cli -- extract -a archive.arc -o ./restored/ -p "algo2026"
```

### Параметри командного рядка
* `-i, --input` — список вхідних файлів для додавання в архів.
* `-o, --output` — шлях до вихідного архіву (`.arc`) або каталог для розпакування.
* `-p, --password` — пароль для генерації ключів шифрування ($K_{\text{enc}}$) та автентифікації ($K_{\text{mac}}$).
* `-a, --archive` — шлях (або перелік шляхів до томів) архіву для розпакування.
