#### Учасник 1: Стиснення (Гаффман) + Розбір потоку (LZ77)

- **Контракт (Вхід / Вихід):**
    
    - Вхід: сирий масив байтів блока (`ReadOnlySpan<byte>`).
        
    - Вихід: масив токенів LZ77 (літерали та пари `(distance, length)`), стиснутий бітовий масив (`byte[]`), три таблиці довжин канонічних кодів (`LIT`, `LEN`, `DIST`) та розмір `coded_len`.
        
- **Перший Unit-тест:**
    
    - `Huffman_DegenerateAlphabet_EncodesSingleSymbolCorrectly`: рядок з одного символу (`AAAAAA`) створює таблицю `LIT` з довжиною коду 1 і бітом `0`.
        
- **Перелік тасків для беклогу (Issues):**
    
    1. `[Issue #11]` Реалізувати ковзне вікно (32768 байтів) та пошук збігів (довжина 3…258).
        
    2. `[Issue #12]` Реалізувати жадібний розбір потоку (Greedy LZ77).
        
    3. `[Issue #13]` Реалізувати лінивий розбір потоку (Lazy Greedy LZ77).
        
    4. `[Issue #14]` Реалізувати побайтовий декодер LZ77 із підтримкою перекриття ($\text{distance} < \text{length}$).
        
    5. `[Issue #15]` Реалізувати чергу з пріоритетами (Priority Queue) та підрахунок частот байтів.
        
    6. `[Issue #16]` Реалізувати генератор канонічних кодів Гаффмана за довжинами (алгоритм 3.4 специфікації).
        
    7. `[Issue #17]` Реалізувати обмеження довжини коду до 15 біт і перевірку рівності Крафта ($\sum 2^{-L} = 1$).
        
    8. `[Issue #18]` Реалізувати побітовий запис/читання (`BitWriter`, `BitReader`) MSB-first із нульовим доповненням останнього байта.
        
- **Точки делегування Helper'у:**
    
    - Відокремлений модуль `BitWriter/BitReader`.
        
    - Реалізація лінивої евристики (Lazy Greedy) як надбудови над готовим базовим поисковиком збігів.
        

#### Учасник 2: Аналіз даних (Перцептрон) + Пакування в томи (Рюкзак 0/1)

- **Контракт (Вхід / Вихід):**
    
    - Вхід для аналізу: початкові байти файлу (`byte[]`).
        
    - Вихід для аналізу: числовий вектор із 6 ознак $\to$ цільовий тип файлу ($0\dots 6$) $\to$ прапорець вибору стратегії (стискати або ввімкнути `NO_COMPRESSION`).
        
    - Вхід для пакування: список блоків-кандидатів (із вагою $\text{coded\_len} + 15$ байтів і пріоритетом типу як цінністю) та ліміт місткості тому $W$.
        
    - Вихід для пакування: список індексів блоків, відібраних у поточний том (решта передається далі).
        
- **Перший Unit-тест:**
    
    - `Knapsack_SmallDataset_MatchesBruteForce`: перевірка ДП-рюкзака проти повного перебору на 10 випадкових предметах.
        
- **Перелік тасків для беклогу (Issues):**
    
    1. `[Issue #21]` Реалізувати розрахунок 6 ознак файлу: байтова ентропія, гістограма (32 кошики), частка ASCII, відстань між переносами рядків, автокореляція (лаги 1…16), ентропія біграм.
        
    2. `[Issue #22]` Реалізувати архітектуру MLP (Fully Connected шари, ваги, активації) без сторонніх ML-бібліотек.
        
    3. `[Issue #23]` Реалізувати прямий прохід (forward pass) та зворотне поширення помилки (backpropagation).
        
    4. `[Issue #24]` Створити навчальний цикл: тренування на `train/`, вибір кращої моделі за `macro-F1` на `valid/` із трьох ініціалізацій.
        
    5. `[Issue #25]` Реалізувати точний алгоритм динамічного програмування для рюкзака 0/1 ($O(n \cdot W)$) із відновленням відповіді.
        
    6. `[Issue #26]` Реалізувати жадібний рюкзак (сортування за відношенням цінність/вага) для обов'язкового порівняння з ДП.
        
    7. `[Issue #27]` Реалізувати розрахунок чистої місткості тому: $W = \text{max\_volume\_bytes} - 41 - 32 - 6 - \text{file\_table\_size}$.
        
- **Точки делегування Helper'у:**
    
    - Модуль екстракції окремих складних ознак (автокореляція та ентропія біграм).
        
    - Реалізація жадібного алгоритму рюкзака та скрипта порівняння з ДП.
        

#### Учасник 3: Захист (Криптографія) + Оптимізація (Генетичний алгоритм)

- **Контракт (Вхід / Вихід):**
    
    - Вхід криптографії: зібраний серіалізований `payload` тому, пароль користувача (`string`), згенеровані випадкова `salt` (16B) та `nonce` (12B).
        
    - Вихід криптографії: `ciphertext` зашифрованого навантаження, 32 байти `HMAC-SHA256` тегу та відкриті службові поля для 41B заголовка.
        
    - Вхід ГА: робочий конвеєр архіватора та навчальний набір даних.
        
    - Вихід ГА: оптимізована трійка параметрів `[window_size, min_match, no_comp_threshold]`, що максимізує метрику $Q$.
        
- **Перший Unit-тест:**
    
    - `Crypto_TamperedCiphertext_ThrowsHmacException`: зміна одного байта в зашифрованому масиві викликає код помилки `E_HMAC` без падіння за винятком десеріалізації.
        
- **Перелік тасків для беклогу (Issues):**
    
    1. `[Issue #31]` Реалізувати KDF: `PBKDF2-HMAC-SHA256` (100 000 ітерацій, 16B солі, результат 64B: 32B $K_{enc}$, 32B $K_{mac}$) з однократним виконанням на сесію.
        
    2. `[Issue #32]` Реалізувати шифрування/розшифрування `AES-256-CTR` (лічильник $nonce(12) \parallel uint32\_BE(i)$, нумерація блоків лічильника з 1).
        
    3. `[Issue #33]` Реалізувати механізм генерації унікального `nonce` для кожного окремого тому в межах одного архіву.
        
    4. `[Issue #34]` Реалізувати перевірку `HMAC-SHA256` у постійний час (constant-time) суворо до початку розшифрування.
        
    5. `[Issue #35]` Описати модель хромосоми ГА з 3 параметрів із валідацією діапазонів значень.
        
    6. `[Issue #36]` Реалізувати оператори ГА: турнірна селекція, одноточковий кросовер, випадкова мутація.
        
    7. `[Issue #37]` Реалізувати механізм елітизму та базовий генератор випадкового пошуку (Random Search) для обов'язкового порівняння.
        
- **Точки делегування Helper'у:**
    
    - Реалізація Random Search baseline з фіксацією результатів.
        
    - Тести на відомі вектори (Known Answer Tests) для AES та HMAC.
        

#### Учасник 4: Інтеграція та системний тракт

- **Контракт (Вхід / Вихід):**
    
    - Вхід (архівування): шляхи до вихідних файлів, пароль, конфігурація.
        
    - Вихід (архівування): сформовані та записані на диск файли томів `.arc` (`.part*.arc`) суворо за специфікацією SARC v1.
        
    - Вхід (розархівування): файли томів архіву, пароль, шлях призначення.
        
    - Вихід (розархівування): розпаковані файли, ідентичні оригіналам, перевірені за `CRC32` та `orig_size`.
