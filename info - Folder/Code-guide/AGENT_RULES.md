# Правила для ШІ-агентів та розробників (AGENT RULES — SARC v1)

Цей документ визначає жорсткі обмеження («що МОЖНА» і «що ЗАБОРОНЕНО») для будь-яких ШІ-агентів (Antigravity, Gemini, Claude, ChatGPT, GitHub Copilot, Cursor тощо) та учасників команди під час роботи над проєктом **SmartSecureArchiver (`Bychkov.arc`)**.

---

## 1. Правила роботи з папкою `team/` (Тільки читання — Read-Only)

* **СУВОРО ЗАБОРОНЕНО** змінювати, перезаписувати, видаляти або перейменовувати будь-які файли в каталозі `team/` (зокрема `team_config.json`, `train/`, `valid/`, `corpus/`, `reference/`). Це еталонні вхідні дані та тренувальні вибірки, видані викладачем із фіксованим seed команди.
* **ДОЗВОЛЕНО** читати конфігураційні та метадані (`team_config.json`, `labels.csv`, `reference/*.json`, `expected_failures.json`) для налаштування конвеєра, навчання перцептрона та перевірки автотестів.
* Великі бінарні вибірки (`train/`, `valid/`, `corpus/`) слід обробляти програмно під час запуску C#-коду, скриптів навчання або автотестів `dotnet test`, не завантажуючи всі сирі файли одночасно у контекст чату.

---

## 2. Що ЗАБОРОНЕНО в коді (Академічна доброчесність, множник $M = 1.0$)

Згідно з розділом 2.2 «Методичних вказівок» та п. 11.4 ТЗ «Проєкт 2», використання готових бібліотек для навчальних алгоритмів курсу обнуляє або зменшує вдвічі оцінку за проєкт:

1. **ЗАБОРОНЕНО використовувати сторонні або стандартні бібліотеки стиснення в робочому тракті архіватора:**
   * Заборонені: `System.IO.Compression` (`DeflateStream`, `GZipStream`, `BrotliStream`, `ZLibStream`, `ZipArchive`), `SharpZipLib`, `K4os.Compression.LZ4`, `SevenZip` та будь-які аналоги.
   * *Виняток:* виклик `ZipArchive` дозволений **виключно** в окремому ізольованому benchmark-скрипті як зовнішній еталон для порівняння у звіті з явною позначкою в коді.
2. **ЗАБОРОНЕНО використовувати бібліотеки машинного навчання:**
   * Заборонені: `ML.NET`, `TensorFlow.NET`, `TorchSharp`, `Accord.NET`, `MathNet.Numerics` (для нейромереж), `ONNX Runtime` тощо.
   * Багатошаровий перцептрон (шари, ініціалізація ваг, функції активації, `Softmax`, прямий прохід `Forward`, зворотне поширення `Backpropagation`, розрахунок `macro-F1` та матриці помилок) і всі 6 груп статистичних ознак реалізуються **виключно власноруч з нуля**.
3. **ЗАБОРОНЕНО використовувати готові бібліотеки оптимізації та графів/ДП:**
   * Заборонені: `GeneticSharp`, `Google.OrTools` та інші солвери.
   * Алгоритм рюкзака 0/1 (ДП за $O(n \cdot W)$ і жадібний алгоритм за $v/w$) та Генетичний алгоритм (турнірна селекція, кросовер, мутація, елітизм) пишуться **виключно власноруч з нуля**.
4. **ЗАБОРОНЕНО сліпо генерувати код без декларування:**
   * Кожне суттєве застосування ШІ-агента обов'язково фіксується новим записом у файлі [`META-USAGE.md`](../../META-USAGE.md) (та [`info - Folder/META-USAGE.md`](../META-USAGE.md)).

## 3. Що ДОЗВОЛЕНО використовувати (стандартна бібліотека .NET 8)

1. **Криптографічні примітиви (`System.Security.Cryptography`):**
   * `Rfc2898DeriveBytes.Pbkdf2` з `HashAlgorithmName.SHA256` для виведення 64-байтного майстер-ключа (`PBKDF2-HMAC-SHA256`, 100 000 ітерацій).
   * `Aes.Create()` (у режимі `CipherMode.ECB` з `PaddingMode.None` для шифрування 16-байтних блоків лічильника `nonce(12B) || uint32_BE(i)` власної реалізації режиму `AES-256-CTR`).
   * `HMACSHA256` для обчислення 32-байтного тегу автентичності.
   * `CryptographicOperations.FixedTimeEquals` для порівняння HMAC у постійний час.
   * `RandomNumberGenerator.Fill` для генерації криптостійких випадкових `salt` (16B) та префіксу `nonce` (8B).
2. **Робота з бінарними буферами та пам'яттю:**
   * `System.Buffers.Binary.BinaryPrimitives` для читання та запису всіх `uint16` і `uint32` у форматі **Big-Endian**.
   * `Span<byte>`, `ReadOnlySpan<byte>`, `Memory<byte>`, `ArrayPool<byte>`.
3. **Системні утиліти та тестування:**
   * `System.IO` (потокове читання/запис файлів), `System.Diagnostics.Stopwatch` (вимірювання часу $t$), `System.Text.Json` (читання `team_config.json`, `expected_failures.json` та збереження результатів експериментів), фреймворк `xUnit` для автотестів.

## 4. Жорсткі правила бінарного контракту `FORMAT_SPEC_P2_2.md` (Порушення = $Q = 0$)

Агентам **ЗАБОРОНЕНО** відхилятися від специфікації `FORMAT_SPEC_P2_2.md` навіть на один біт:

1. **Порядок байтів і бітів:**
   * Усі багатобайтові цілі числа — **Big-Endian**, беззнакові (`uint16`, `uint32`).
   * Побітовий потік пакується **старшим бітом уперед (MSB-first)**: перший записаний біт стає бітом `0x80` першого байта. Останній байт доповнюється **нулями** до межі байта (ненульові біти доповнення при читанні викликають `E_CODE`).
2. **Зовнішній заголовок тому (рівно 41 байт, відкритий текст):**
   * `[0..3]` `magic` = ASCII `"SARC"` (`53 41 52 43`)
   * `[4]` `version` = `1` (`uint8`)
   * `[5..6]` `volume_index` (`uint16`, від `0`)
   * `[7..8]` `volume_count` (`uint16`)
   * `[9..24]` `salt` (16 байтів, **однакова для всіх томів одного архіву**)
   * `[25..36]` `nonce` (12 байтів, **різний для кожного тому**, схема: `8B prefix || uint32_BE(volume_index)`)
   * `[37..40]` `ciphertext_len` (`uint32`)
   * Повна довжина файлу тому: `41 + ciphertext_len + 32` (де останні 32 байти — `HMAC-SHA256`). Менше 73 байтів $\to$ `E_SHORT`.
3. **Криптографія та порядок перевірок у розархіваторі:**
   * **ЗАБОРОНЕНО** використовувати один ключ для шифрування і HMAC. `master = PBKDF2(password, salt, 100000, 64)` $\to$ `K_enc = master[0..31]`, `K_mac = master[32..63]`.
   * **ЗАБОРОНЕНО** викликати `PBKDF2` для кожного тому окремо — ключі виводяться **один раз на архів**.
   * У `AES-256-CTR` перший блок лічильника має номер **`i = 1`** (не `0`!): `counter_block(i) = nonce(12B) || uint32_BE(i)`.
   * **ЗАБОРОНЕНО** розшифровувати шифротекст до перевірки `HMAC-SHA256` у постійний час. Невірний пароль або змінений байт повинен негайно повертати `E_HMAC`.
4. **Структура зашифрованого Payload (суворий порядок без вирівнювань):**
   * `file_count` (`uint16`), `flags` (`uint8`, для базового рівня `= 0`), `reserved` (`uint8 = 0`). Ненульовий `reserved` або невідомі біти `flags` $\to$ `E_PAYLOAD`.
   * **Таблиця файлів** (`file_count` записів): `name_len` (`uint16`), `name` (UTF-8 без `\0`), `orig_size` (`uint32` цілого файла), `crc32` (`uint32` цілого файла), `file_type` (`uint8`, `0..6`, якщо `> 6` $\to$ `E_PAYLOAD`), `strategy` (`uint8`).
   * **Безпечні імена файлів:** якщо ім'я порожнє, дорівнює `.` або `..`, містить `/`, `\`, `:`, `\0` або є абсолютним шляхом — негайно відхилити архів із `E_PAYLOAD` **до** будь-якого запису на диск.
   * `block_count` (`uint16`) — іде **після** таблиці файлів!
   * **Таблиця блоків** (`15 × block_count` байтів): `file_index` (`uint16`), `block_seq` (`uint32` — **4 байти!**), `raw_len` (`uint32`), `coded_len` (`uint32`), `block_flags` (`uint8`, біт 0 = `NO_COMPRESSION`, біти 1..7 `= 0`).
   * **Дані блоків:** склеєні підряд.
5. **Кодування стисненого блоку (LZ77 + Канонічний Гаффман):**
   * Параметри LZ77: `MIN_MATCH = 3`, `MAX_MATCH = 258`, вікно `32768`.
   * Три окремі дерева: `LIT` (`0..256`, де `256` — маркер посилання), `LEN` (`0..255` = `length - 3`), `DIST` (`0..15`, символ `>= 16` $\to$ `E_CODE`).
   * Кодування відстані `1 <= dist <= 32768`: `d = dist - 1`, `code = bit_length(d)` (`0` при `d = 0`), `extra = max(0, code - 1)`. Спочатку пишеться код Гаффмана `DIST(code)`, далі `extra` молодших бітів числа `d` старшим бітом уперед без кодування.
   * Серіалізація кожної з 3 таблиць: `nsym` (`uint16`), далі `nsym` записів по 3 байти за **зростанням символу**: `symbol` (`uint16`), `length` (`uint8`, `1..15`). Далі `token_count` (`uint32`), `stream_len` (`uint32`), `stream` (`stream_len` байтів).
   * Вироджений випадок (`nsym == 1`): `length = 1`, `code = 0`. При `nsym > 1` обов'язкова точна рівність Крафта $\sum 2^{-L_i} = 1$ (інакше `E_CODE`).
6. **Пакування в томи (Рюкзак 0/1):**
   * Вага блока: $w = \text{coded\_len} + 15$.
   * Таблиця всіх файлів-кандидатів поточного тому фіксується **ДО** запуску рюкзака: $W = \text{max\_volume\_bytes} - 41 - 32 - 6 - \text{file\_table\_size}$. Змінювати склад таблиці файлів після вибору блоків **ЗАБОРОНЕНО**.
7. **Коди відмови (жодних необроблених винятків на пошкоджених даних):**
   * Будь-яка помилка валідації архіву має повертати точний код `SarcErrorCode`: `E_SHORT`, `E_MAGIC`, `E_LENGTH`, `E_HMAC`, `E_PAYLOAD`, `E_CODE`, `E_CRC`, `E_VOLUMES`.

## 5. Правила роботи з репозиторієм та архітектурою

1. **Дотримання контрактів у `SmartSecureArchiver.Core`:** не змінювати сигнатури спільних інтерфейсів без синхронного оновлення всіх реалізацій та тестів.
2. **Гілки та коміти:** працювати у feature-гілках, прив'язувати коміти до номерів задач з [`info - Folder/Issue.md`](../Issue.md) (наприклад, `feat: implement canonical Huffman encoder (#16)`).
3. **Чистота репозиторію:** не додавати у Git скомпільовані бінарники (`bin/`, `obj/`), тимчасові файли `.tmp` та паролі/ключі у відкритому вигляді.
4. **Обов'язкова перевірка перед завершенням задачі:** кожна зміна має проходити `dotnet build SmartSecureArchiver.sln` та `dotnet test SmartSecureArchiver.sln` без помилок і попереджень.
