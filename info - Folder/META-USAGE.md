# Декларація використання інструментів генерації коду та ШІ (META-USAGE)

Цей файл призначений для регламентування та прозорої фіксації використання ШІ в розробці проєкту «Розумний захищений архіватор файлів SARC v1».

> «Можна використовувати інструмент, але не можна передавати йому відповідальність за розуміння власного проєкту.»  
> *(Методичні вказівки до проєкту)*

---

## 1. Внутрішній регламент команди

1. **Особиста відповідальність:** Кожен учасник команди зобов'язаний розуміти роботу кожного рядка коду у своїй зоні та бути готовим пояснити його алгоритмічну складність, роботу з пам'яттю і крайові випадки на захисті без сторонніх підказок.
2. **Обов'язкова верифікація:** Жоден фрагмент згенерованого коду не потрапляє в `main` без ручного рев'ю, адаптації під стиль проєкту та покриття автоматичними unit-тестами.
3. **Чесність журналювання:** Будь-яка допомога LLM (ChatGPT, Claude, Gemini тощо) або GitHub Copilot у проєктуванні архітектури, генерації тестів чи налагодженні алгоритмів фіксується новим записом у цьому документі.
4. **Заборона сліпого копіювання:** Заборонено генерувати алгоритми цілком без звірки зі специфікацією `FORMAT_SPEC_P2` (зокрема щодо порядку байтів Big-Endian, меж вікна LZ77 та структури заголовків).
5. **Що не передавалося ШІ:** Приховані тестові вибірки, закриті матеріали викладача та паролі/секретні дані.

---

## 2. Структура запису (Шаблон)

Кожне звернення до генеративних інструментів фіксується за формою:
* **Запис №:** порядковий номер.
* **Дата:** РРРР-ММ-ДД.
* **Учасник:** ПІБ або роль у проєкті.
* **Інструмент:** назва моделі / сервісу (наприклад, Gemini, ChatGPT, Copilot).
* **Задача / Промпт:** опис проблеми або ключові тези запиту.
* **Згенерований результат:** що саме запропонував інструмент (архітектура, код, тест, документація).
* **Внесені зміни:** що було переписано, оптимізовано чи видалено вручну.
* **Метод верифікації:** якими тестами, компілятором чи звіркою зі специфікацією перевірено працездатність.
